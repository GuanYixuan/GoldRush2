# NPC ID 无关性分析

本文基于已导出的 NPC 特征表，检查 NPC 行为是否需要显式依赖 `npc_id`。结论先行：当前数据支持第一版建模中把 NPC 行为视为近似与 id 无关；保留 `npc_id` 作为诊断字段即可，不建议先加入 id 专属策略参数。

## 数据范围

输入特征表：

```text
mechanism/data/processed/npc_features/<run_id>/
```

分析批次：

- 地图1：`symobs-a-map1-100-20260727-231446`
- 地图2：`symobs-a-map2-100-20260727-231704`

只使用连续可见 NPC 轨迹，即同一轮 `start.npcs[id]` 和 `end.npcs[id]` 均可见，且动作可重放。

## 调度顺序

此前已确认两图均观察到全部 `7! = 5040` 种 NPC 内部排列。分 id 看，各 NPC 出现在 7 个内部调度位置的次数接近均匀，没有固定先后顺序。

例如合并后每个 id 都约有 `97600` 条连续轨迹。单图中每个 id 在每个 dispatch index 的计数约为 `6900..7100`，符合随机排列的规模波动。

结论：NPC 内部调度不需要按 id 建模，第一版可直接使用随机 permutation。

## 结论

当前数据支持以下建模选择：

```text
NPC policy does not depend on npc_id
```

建议第一版 NPC 行为模型：

- 不引入 `npc_id` 专属动作参数。
- 使用共享策略参数。
- 保留 `npc_id` 作为诊断、分层验证和残差分析字段。
- 若后续模型残差显示某些 id 在同等局部上下文下仍有稳定偏差，再考虑加 id random effect，而不是一开始写死 id-specific policy。

当前更值得优先建模的因素是：

1. `step_idx`
2. 局部金币
3. 局部炸弹
4. 几何/区域/中心距离
5. 调度顺序和先手玩家已改变的局面

id 间无条件 pickup / bomb trigger 的波动存在，但跨图不稳定，且条件响应高度一致；它们更像轨迹和观测上下文差异，不足以支持“NPC 行为依赖 id”的结论。
