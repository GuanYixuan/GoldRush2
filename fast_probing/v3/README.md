# fast_probing v3 视野贪心策略

v3 基于 v2 的无 BFS 曼哈顿贪心策略，加入低信息状态下的视野购买。目标是保持 v2 的快速响应，同时减少“金币被炸弹/障碍挡住却持续吸引角色”的空转。

实现仍采用相对 include 引用官方接口：`../../official_sdk/code/game_api.h`。

## 核心思路

- 目标选择保持 v2：扫描 `17x17 grid`，选 `grid > 0` 且 `min(md0, md1) <= 6` 的最大金币堆。
- 移动保持 v2：主行动角色逐步向目标贪心移动，每步只检查候选方向安全性。
- 到达金币目标后，只在仍有拾取收益时执行有限次“退出-再进入”。
- 主角色完成必要动作后，剩余步数交给副角色向中心 `(8,8)` 移动，减少单角色长期活跃、另一角色停在角落的问题。
- fallback 保持 v2：没有候选金币时，随机选一个角色向中心 `(8,8)` 贪心移动。
- 新增视野规则：连续 2 回合没有成功抵达 `>1` 的金币目标时，本回合购买一次 `9x9` 视野，即 `vp=2`。

## “可抵达”的折中定义

v3 不恢复 BFS，因此“可抵达”不是严格路径可达。这里采用折中判据：

- 若本回合选中了金币目标，且目标金币数 `>1`，并且当前贪心动作实际走到了目标格，则认为本回合有可抵达高价值金币。
- 否则认为本回合没有可抵达高价值金币。

这会把以下情况计为坏回合：

- 没有曼哈顿 6 步内金币。
- 只有 `1` 金币小堆。
- 选中了 `>1` 金币，但贪心被炸弹、障碍、迷雾、敌人或拥挤格挡住，最终没走到。
- fallback 向中心。

若连续 2 个坏回合出现，则购买一次 `9x9` 视野，并重置计数。

## 状态与费用控制

- 使用静态计数器保存连续坏回合数。
- `input->round == 0` 时重置计数，避免跨局污染。
- 购买 `vp=2` 后立刻清零。
- 第一版不加额外冷却；若实测 `vision_spent` 过高，再考虑买后冷却若干回合。

## 有收益 bounce 阈值

按规则，每次进入金币格拾取当前地面金币的 `ceil(65%)`。精确模拟可得：

- `1..2` 金币：一次进入即可耗尽。
- `3..8` 金币：两次进入即可耗尽。
- `9..25` 金币：三次进入即可耗尽。

单回合最多 6 步，因此当前实现只硬编码到三次进入。若主角色已经通过移动进入过目标，则这次进入已发生，后续额外 bounce 上限为：

- `gold <= 2`：`0` 次。
- `3 <= gold <= 8`：`1` 次。
- `gold >= 9`：`2` 次。

如果角色本回合一开始就在金币格上，因为原地不会拾取，则第一次“退出-再进入”仍可能有收益。

## 速度预期

v3 只在动作生成时多返回一个 `reached` 布尔，并维护一个小计数器。目标选择不额外模拟所有候选金币，因此 P90 预计接近 v2 的约 `1.1us`。

## 实测关注

- P90 是否仍接近 v2。
- `vision_spent` 是否过高。
- 毛金币和扣除视野费用后的净金币是否改善。
- 被炸弹/障碍挡住时是否减少无意义来回移动。
