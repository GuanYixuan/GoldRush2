# fast_probing v1 策略理解

本版本目标是快速得到一个可编译、低复杂度、规则保守的 C++ 策略。实现路径采用相对 include 引用官方接口，例如从 `fast_probing/v1/player.cpp` 引用 `../../official_sdk/code/game_api.h`。

## 核心约束：快

GoldRush2.0 每回合按策略耗时决定两名玩家行动先后；耗时更短的一方先行动，同一金币或炸弹由先执行者获取或触发。因此 v1 的策略价值不只来自路径质量，也来自响应速度。

v1 设计上应优先保证决策极快：

- 不做全局规划，不跑大规模搜索。
- BFS 深度不超过 `6`，因为单回合总步数最多就是 `S=6`。
- 两个角色各跑一次半径 6 的局部 BFS，最多覆盖很小的已知格集合。
- 目标只从当前可见金币中选择，并且只评估 BFS 可在 6 步内触达或接近的目标。
- 不维护复杂跨回合状态，不做动态分配、对手预测或概率估计。
- 不做日志 I/O，不使用随机设备作为每回合依赖，不引入堆分配密集的数据结构。
- 编译期使用 `-O2`，运行期使用固定大小数组、简单队列和整数比较。
- 当前实现已把每回合安全格预计算为固定数组，BFS 内层只做数组查询；BFS 状态使用 `int8_t`/`uint8_t`，避免存储完整前驱坐标。

若策略质量和响应速度冲突，v1 优先响应速度。这个版本应作为一个“足够合理且极快”的基线，而不是追求最优路径。

## 输入与可用信息

- 只使用本轮 `GameInput` 提供的信息，不维护复杂长期地图。
- `grid` 是当前可见范围内的纯地形和金币信息：
  - `-5`：迷雾，不确定，v1 视为不可 BFS 穿越。
  - `-3`：炸弹，v1 BFS 避开。
  - `-1`：障碍，必须避开。
  - `0`：空地。
  - `>=1`：可见金币堆，值为该格金币数。
- 我方两个角色位置来自 `my_units[0..1]`，角色不在 `grid` 中标记。
- 可见敌人来自 `visible_enemies`，v1 把有效敌人格视为不可进入，降低碰撞风险。
- 可见 NPC 不阻挡玩家移动，但若同格 NPC 数量 `>=3` 会触发拥挤踩踏。v1 把这种格子作为高风险格避开（认为不可走即可）。

## 目标选择

- 每回合先对两个角色分别从当前位置 BFS，BFS 深度最多为 `6`，只在已知可通行格上运行：
  - 不越界。
  - 不进入障碍。
  - 不进入炸弹。
  - 不进入迷雾。
  - 不进入可见敌人当前格。
  - 先不进入另一个我方角色当前格。
- BFS 完成后，只在本回合 6 步内至少有一个角色可达的可见金币堆中选目标。
- 目标优先级：
  - 先选 `grid[row][col]` 最大的可达金币堆。
  - 金币数并列时，选两个角色 BFS 距离中较小者更近的金币堆。
  - 仍并列时按扫描顺序稳定选择。
- 选择到该目标 BFS 距离更短的角色作为主行动角色。
- 主行动角色沿 BFS 路径直接去目标金币堆，并在剩余步数允许时尝试“进入-退出-再进入”。
- 若没有本回合可达的可见金币堆，则 fallback 走保守探索或原地：
  - 随机选取一个角色作为主行动角色。
  - 该角色尽量向棋盘中心 `(8,8)` 移动。
  - 单回合内每一步都必须落在本轮输入视野中的已知安全格，不能为了靠近中心进入迷雾。
  - 已知安全格至少要求不是障碍、炸弹、可见敌人、另一个己方角色当前格、NPC 数量 `>=3` 的拥挤格。
  - 每一步从安全候选动作中选择让曼哈顿距离中心更小的动作；若没有更优动作，可选择任意安全动作继续探索。
  - 若没有安全可行动作，则 `STAY`。

## 行动分配

- 第一版为了简单，倾向把 6 步全部给最近角色：`k=6` 或 `k=0`。
- 若角色 0 是主行动角色：
  - `actions[0..5]` 为角色 0 路径动作。
  - `k=6`。
  - `order=0`。
- 若角色 1 是主行动角色：
  - `actions[0..5]` 为角色 1 路径动作。
  - `k=0`。
  - `order=1` 或 `order=0` 都不会让角色 0 实际移动；为语义清晰可用 `order=1`。
- 非主角色不移动，避免自家角色交换、穿越或阻塞的复杂判定。

## 金币拾取与“进入-退出-再进入”

规则关键点：

- 角色只有从其他格移动到有金币的格子时才拾取金币。
- 金币生成或角色原地停在金币格上，不会自动拾取。
- 同一角色离开再进入同一金币格，可以重复拾取。
- 每次拾取获得当前该格金币数的 `ceil(65%)`，地面理论上留下剩余部分。

因此，若主角色能在本轮到达目标金币格，并且剩余步数足够，v1 可以尝试：

1. 沿 BFS 最短路进入金币格，触发第一次拾取。
2. 从金币格移动到一个安全相邻格。
3. 再移动回金币格，触发第二次拾取。
4. 若还有步数且存在安全相邻格，可重复该往返。

该策略需要满足：

- 退出格不是障碍、炸弹、迷雾、可见敌人、另一个我方角色当前格。
- 退出再进入的两步都合法。
- 优先选择能回到目标格的安全相邻格。
- 如果目标金币格距离为 `d`，则第一次进入需要 `d` 步；每次额外重复拾取需要 `2` 步。
- 若 `d == 0`，角色已经站在金币格上，本轮原地不会拾取；可以先走到安全相邻格再回到金币格，至少需要 `2` 步。

v1 不在本地精确模拟拾取后金币剩余值，只把“可重复进入”作为固定收益启发式。因为单回合最多 6 步，面对大金币堆时该启发式通常值得尝试。

## 视野购买

- `vp` 费用赛后扣除，且购买下回合才生效。
- v1 暂时不购买视野

## 明确不做

- 不推断金币生成分布。
- 不用快照估算隐藏金币。
- 不预测 NPC 移动。
- 不预测对手耗时先后手。
- 不做跨回合地图记忆。
- 不做两个角色协同分配多个金币堆。

这些都留给后续版本。
