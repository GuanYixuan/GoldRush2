# fast_probing v2 贪心策略

v2 目标是继续压低 `moveDecision` 耗时，用更弱的路径质量换先手速度。相较 v1，v2 完全移除 BFS，不做全图安全格预计算，不做路径可达性证明，只用曼哈顿距离和逐步贪心。

实现仍采用相对 include 引用官方接口：`../../official_sdk/code/game_api.h`。

## 核心思路

- 每回合扫描 `17x17 grid`，找可见金币堆。
- 对金币堆只计算两个角色到目标的曼哈顿距离。
- 优先选择 `min(md0, md1) <= 6` 的最大金币堆。
- 金币数并列时选更近的目标，仍并列按扫描顺序稳定选择。
- 选最近角色作为主行动角色，给它全部 6 步。
- 主行动角色逐步向目标贪心移动；每步只检查少量候选方向。
- 到达目标后若还有步数，尝试“退出-再进入”重复拾取。
- 无 `md <= 6` 的可见金币时，fallback 为随机选一个角色向中心 `(8,8)` 贪心移动。
- `vp=0`，不购买视野。

## 安全判断

v2 不预计算 `safe[2][17][17]`。每步只对候选动作做 inline 安全判断：

- 不越界。
- 不进入迷雾 `-5`。
- 不进入炸弹 `-3`。
- 不进入障碍 `-1`。
- 不进入另一个己方角色当前格。
- 不进入可见敌人当前格。
- 不进入可见 NPC 数量 `>=3` 的拥挤格。

该判断只覆盖当前输入视野下已知风险。v2 不推断未知地图，不预测 NPC 或对手移动。

## 与 v1 的差异

- v1：两个角色各做深度 6 BFS，只选择本回合真实可达金币。
- v2：只用曼哈顿距离近似可达性，遇到绕墙场景可能无法抵达目标。
- v1：P90 平台实测约 `3.5-4.2us`，行为不变优化后 self-play 约 `3.6us`。
- v2：目标是显著低于 v1，若仍不能接近 `1us`，后续可继续删除敌人/NPC 检查或改成固定角色贪心。

## 风险

- 曼哈顿距离不等于真实路径距离，墙和炸弹会让目标不可达。
- 逐步贪心可能被障碍卡住。
- 因为不做 BFS，可能错过需要绕一步才能吃到的金币。
- 若低延迟带来的先手收益不足以弥补路径损失，胜率可能低于 v1。
